# AIエージェントの利用ルール

このドキュメントは、開発で AI エージェントを使うときのルールをまとめたものです。対象はプロダクト開発部の全メンバーです。

## 使ってよいツール

会社契約の AI コーディングエージェントを使ってください。個人契約のアカウントで社内コードを扱うのは禁止です。

| ツール | 用途 | 社内コードを渡せるか | 申請 |
| --- | --- | --- | --- |
| 会社契約のコーディングエージェント | 実装・調査・レビューの補助 | 渡せる | 不要 |
| 会社契約のチャット AI | 調べもの・文章の下書き | 渡せる | 不要 |
| これ以外の AI サービス | 用途による | 渡せない | セキュリティ担当へ申請 |
| 個人契約のアカウント | 業務では使わない | 渡せない | 受け付けません |

新しいツールを使いたいときはセキュリティ担当に申請してください。返事の目安は3営業日です。

## やってよいこと・やってはいけないこと

| やってよいこと | やってはいけないこと |
| --- | --- |
| 実装の下書きを書かせる | 差分を読まずに取り込む |
| テストコードを書かせる | テストの結果を見ずに提出する |
| 既存コードの意味を説明させる | 説明をそのまま仕様書として扱う |
| 障害の原因の候補を挙げさせる | 挙がった候補を確かめずに報告する |
| ドキュメントの下書きを書かせる | 社外に出す文章を読まずに送る |

## 渡してよい情報

顧客データ・認証情報・個人情報をプロンプトに貼らないでください。判断に迷ったらセキュリティ担当に相談してください。

| 情報 | 渡してよいか |
| --- | --- |
| 社内リポジトリのソースコード | 渡してよい |
| エラーログ（個人情報を消したもの） | 渡してよい |
| 設計メモ・仕様の下書き | 渡してよい |
| 本番のデータベースの中身 | 渡さない |
| API キー・パスワード・トークン | 渡さない |
| お客さまの氏名・連絡先・契約内容 | 渡さない |

ログを貼るときは、メールアドレスと ID を伏せてから貼ってください。

## レビュー

AI が書いたコードも、人が書いたコードと同じレビューを通します。差分を読まずに取り込むのは禁止です。

提出する前に、書いた本人が次を確認します。

- [ ] 差分を最初から最後まで自分で読んだ
- [ ] 実際に動かして、意図どおりか確かめた
- [ ] テストを追加または更新した
- [ ] 使っていないコードや余分なコメントを消した
- [ ] 既存の書き方に合わせた
- [ ] 説明を求められたら自分の言葉で答えられる

> [!WARNING]
> 「AI が書いたので分かりません」は通りません。提出した人が内容の責任を持ちます。

## 記録

AI に大きな変更を任せた場合は、変更提案の説明にその旨を書いてください。

説明欄には次のように書きます。

```
AI エージェントを使った範囲: <どのファイルの、どの処理か>
使ったツール: <ツール名>
人が確認したこと: 差分の全読み、手元での動作確認、テストの追加
気になっている点: <あれば書く。なければ「なし」>
```

「大きな変更」の目安は、100行を超える差分、または複数のファイルにまたがる変更です。迷ったら書いてください。

## 困ったとき

| 相談ごと | 相談先 |
| --- | --- |
| 情報を渡してよいか判断できない | セキュリティ担当 |
| 新しいツールを使いたい | セキュリティ担当 |
| 生成されたコードの良し悪しが分からない | チームのリード |
| このルール自体を変えたい | このドキュメントに変更提案を出す |
